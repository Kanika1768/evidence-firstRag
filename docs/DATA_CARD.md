## 2. Ingested Corpora Description

The EvidenceFirst demonstration and evaluation environment uses two primary data tiers:

### Tier A: Demo & Multi-Corpus Knowledge Base
- **Domain**: Corporate, Organizational, and Computer Networking Technical Knowledge.
- **Corpus Files**:
  1. `company.txt` — NovaTech corporate overview, founding leadership (Priya Mehta), product offerings (analytics software).
  2. `history.txt` — NovaTech organizational history, founding year (2019), San Francisco origins.
  3. `finance.txt` — NovaTech financial audit reports, 2025 annual revenue ($42M).
  4. `CS301_1-2.pdf` — Computer Networks Academic Course Lecture Notes (end systems, packet switching, routing, network edge, IP architecture).
- **Licence & Usage**: Public educational materials and synthetic corporate operational documents created for academic RAG benchmarking under MIT License.
- **Document Count**: 4 documents (3 text corpora + 1 multi-page PDF).
- **Processing Specs**:
  - Target chunk size: **~550 tokens**
  - Overlap: **~80 tokens**
  - Text cleaning: Automated removal of running headers, page numbers ("Page X of Y"), copyright footers, and redundant blank padding.
  - Heading preservation: Markdown `#` headings and capitalized section titles prepended to chunk metadata.
  - Page provenance: Every chunk retains `document_id`, `document_name`, `page`, `section`, and `chunk_id`.

## 3. Evaluation Benchmark Track (Sufficient-Context Set)

- **Total Benchmark Examples**: 80 curated and derived records across 4 public QA datasets:
  1. **PopQA** (Mallen et al., 2023) — Entity-centric open-domain queries with Wikidata entity IDs.
  2. **FreshQA** (Vu et al., 2023) — Fast-changing and false-premise world knowledge queries.
  3. **Natural Questions** (Kwiatkowski et al., 2019) — Real user search queries from Google Search.
  4. **EntityQuestions** (Sciavolino et al., 2021) — Entity-relation queries across diverse Wikidata relations.
- **Controlled Context Strategy**: For each source question, paired controlled contexts are constructed:
  - One candidate **SUFFICIENT** context variant.
  - One candidate **INSUFFICIENT** context variant (omitting critical bridging facts or premises).
- **Annotation Status**:
  - `gold_label`: Strictly initialized to `PENDING` awaiting independent human adjudication.
  - Silver Labels: Generated by independent LLM evaluation in `data/evaluation/independent_llm_annotations.jsonl`.
  - Blinded Human Subset: 40 deterministically sampled records in `data/evaluation/human_verification_subset.jsonl`.

## 4. Processed Artifacts & Storage Formats

| Artifact Path | Format | Description |
| :--- | :--- | :--- |
| `data/processed/chunks.json` | JSON | Structured chunk metadata with page numbers and section headings |
| `data/processed/chunks.parquet` | Parquet / Structured | High-performance columnar chunk storage |
| `data/processed/faiss.index` | Binary Pickle / FAISS | Dense vector index (384-dim, normalized Inner Product / Cosine Similarity) |
| `data/processed/bm25.pkl` | Binary Pickle | Okapi BM25 inverted index ($k_1=1.5, b=0.75$) with precomputed IDF |
| `results/retrieval_ablation.csv` | CSV | Measured Recall@5, Recall@10, and MRR for Dense, BM25, RRF, and Reranker |

## 5. Ethical Considerations & Limitations

- **No Fabricated Data**: Benchmark provenance distinguishes upstream raw IDs from constructed controlled contexts.
- **Human Gold Integrity**: Curator candidate labels are never presented as independent human ground truth.
- **Privacy & PII**: All corporate and networking documents contain synthetic or public academic information with no personal sensitive data.
